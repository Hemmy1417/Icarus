# Architecture

One intelligent contract, one interface, and nothing else. There is no
database, no worker, no indexer and no server-side secret. Everything a page
shows is read from the chain when the page loads, which is why a reader can
check any figure on it without trusting this repository.

## The pieces

```text
  a browser                      GenLayer Studio Next, chain 61997
 ┌──────────────────────┐       ┌────────────────────────────────────┐
 │ web/  Next.js         │reads │ contracts/icarus.py                │
 │  lib/read.ts    ──────┼─────►│  12 views, unsigned                │
 │  lib/kit.ts     ──────┼─────►│  19 writes, signed by the wallet   │
 │  lib/present.ts       │      │  images and documents held on chain│
 └──────────────────────┘      └────────────────────────────────────┘
          ▲                                     ▲
          │ the person's own wallet signs       │ node scripts/proofs.mjs
          │ every write                         │ drives the live proof run
```

## Why the contract holds the evidence

An image could have been referenced by a link. It is stored on chain instead,
and hashed by the contract when it is filed, for three reasons that are worth
the cost:

1. **Every validator judges the same bytes.** A link can serve different
   content to different nodes, and a panel that disagrees because it saw
   different pictures is not a panel.
2. **A later round cannot be misled.** An appeal re-reads the evidence the
   first round judged. If that evidence lived behind a link, the appellant
   could change it between rounds.
3. **A reader can check it.** The interface fetches the bytes, recomputes the
   digest in the browser and says whether it matches what the contract
   recorded. That is a check the reader watches happen, not a claim this site
   makes.

The cost is a hard ceiling: an image is at most 400,000 bytes, and the runner
reads PNG and JFIF-headed JPEG only. The interface redraws and re-encodes
what a person uploads so that the bytes the contract stores are always
readable by the panel.

## Why there is no server

Anything this build ran on a server would be a thing a reader has to trust.
The pages are static; the reads go straight from the visitor's browser to a
Studio Next node, budgeted against that node's rate limit; the writes are
signed by the visitor's own wallet. Nothing in between can alter a figure or
withhold a record.

The one consequence worth naming: the proof log in `web/lib/proof-log.json`
pairs a reading with the transaction that produced it, and a contract cannot
know its own transaction hash. That pairing is generated by
`scripts/proof-log.mjs` from the run's own receipts and committed, and the
interface says where it came from rather than presenting it as something the
chain returned.

## The modules that matter

| Module | What it is responsible for |
|---|---|
| `lib/read.ts` | Every view call. Budgets reads against the node's 30-per-minute limit, retries transient failures, caches what cannot change, and turns a contract refusal back into the contract's own sentence. |
| `lib/present.ts` | Every word a person reads. The contract speaks in `SCREAMING_SNAKE`; a page should not. Identifiers, addresses and digests never reach reading flow from here. |
| `lib/acts.ts` | What each person can do next, as a pure function of the record, the viewer and the chain's clock. An act the contract would refuse is shown with its reason instead of being a button that fails. |
| `lib/kit.ts` | The Transaction Kit bound to the connected wallet. The one write that moves value out of the contract is priced by simulation, because the kit at rc.2 submits without the message allocations that the leader requires. |
| `lib/images.ts` | Redraws and re-encodes an upload to a JFIF JPEG under the size limit, and reads the original's capture date and place so they can be filed as the submitter's claims. |

## The contract's own shape

The contract keeps five maps: projects, milestones, rounds, items and the
ledger, plus the bytes and text of filed evidence. A milestone's terms are
versioned, and a version binds only when both parties have signed it, so
evidence is always judged against terms that were agreed before it was filed.

Nondeterministic work happens in exactly one place: `request_assessment` and
`decide_appeal` both call the same reading and judging pair under
`gl.vm.run_nondet`. Everything else is ordinary deterministic code, which is
why the state machine can be reasoned about without reference to a model.
